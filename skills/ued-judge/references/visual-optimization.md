# 视觉优化执行参考（主控）

用于 Step 5 形成视觉方案、Step 5.5 写入目标稿的视觉契约、Step 7 实施与核验；执行约束统一见 [execution-constraints.md](execution-constraints.md)。不传给评论员，不改变冻结评分。用户指定的品牌、主题、密度与既有设计系统优先。视觉优化不等于换皮，也不授权删除功能或改业务语义。

## 先建立设计契约

对本轮受影响的区域，用一段简短说明确定下列关系，已有 token 优先复用；没有体系时只建立本轮所需的最小集合：

| 关系 | 必须明确的选择 | 核验方向 |
|---|---|---|
| 焦点与构图 | 用户首先要看什么、随后做什么；组间主次与组内关系 | 主行动不被次要指标压过；重点突出后同组仍可成组比较，长页面后半部仍有合理重心 |
| 字体角色 | 标题、正文、辅助说明、数据各自的字号/字重/行高 | 小尺寸和中文长标题仍可分层阅读，不靠整体放大解决层级 |
| 色彩角色 | 主操作、表面、中性文字、业务状态的用途 | 主色来自既有品牌或本次明确选择，不由行业类别自动推成青绿；减少噪音不等于去色 |
| 表面层级 | 哪些区域需要底色、描边、阴影或分隔 | 有意义的分组更清楚；不把“去模板化”误做成去掉所有结构 |
| 间距与密度 | 组内、组间、区域间的节奏与行高；控件可见尺寸、真实点击区域及主要输入方式 | 相关内容靠近，区块有区分；不因点击目标或字号检查全端同比放大，紧凑不牺牲可读性或操作目标 |

若存在两个合理方向，可比较小范围候选并说明取舍；不强制新增方案确认闸门或整页重做，继续遵守已经获批的阶段范围。

## 执行方法

- **先改关系，再改装饰**：焦点、栏目比例、阅读顺序与字体角色优先；不要只换圆角、阴影和颜色，也不要为独特而强制非对称。
- **字体要适合内容**：不强制更换系统字体或引入外部字体。选择支持中文、数字与业务符号的字体；比较数据可用等宽数字，数字与单位保持关联。长文本控制阅读宽度，表格按字段重要性分配列宽，不将所有列等宽。
- **强调有预算**：主行动、风险与数据疑点采用不同角色；控制面积和重复频率，不让背景色块比需要处理的事项更抢眼。语义提示不能仅靠颜色。
- **分组不等于套卡片**：按任务决定使用列表、表格、分隔或面板。已有有效容器可保留，不机械添加纹理、玻璃、渐变、图片或卡片悬浮。
- **组内整体性与主次并存**：指标或其他可比较信息先保持共同的分组关系、对齐、间距与字体角色，再按任务局部强调。共同底色、轻分隔、标题或空间聚合均可建立整体，不强制卡片。首要焦点可以是指标组或任务区域，不要求一个孤立大数字；不要为了突出一项而让其余项失去归属。用于比较的同质结构不自动等于模板化。
- **边框默认低权重，不主动增强**：默认组件边框、装饰描边与辅助分隔不设统一对比度下限，尤其在深色模式下，避免密集亮线压过内容、主行动与真实风险。先按 [hard-checks.md](hard-checks.md) H2 判断实际必要识别线索；控件识别综合考虑填充、可操作文字/图标、位置、间距与上下文，但不能由此自动豁免必要线索。没有明确识别缺陷时保留原有弱边框，不以比值提高作为视觉质量奖励，也不以更低对比本身为目标。
- **装饰、识别、状态分工**：已有 token 优先复用，必要时分开装饰边框、控件识别边界与焦点/选中指示。只修复有识别问题的区域，不为一个输入框全局调亮所有卡片和表格线，也不因降噪全局调暗必要状态。没有必要描边时可用表面或间距建立层次，但不能把有效结构一并清空；保留用户指定的高对比主题。
- **保留轮廓一致性，不新增局部亮边补数值**：默认沿用原有控件的轮廓与样式语言，不为通过对比检查单独强化底边、某一侧或一段边界，也不统一换成下划线输入框。原有设计体系的下划线输入、焦点或选中指示不在此禁令内；没有完整描边的控件不必补成全框。确有必要线索缺陷时，在已批准范围内选择与原有体系一致的修复，核验默认空输入和相关状态；不以静态标签或仅有 hover / focus 替代必要的默认识别，也不统一提亮底色制造新的焦点竞争。
- **对齐包含光学关系**：按 G1 检查控件几何；图标与文字还需比较笔画、字号和视觉中心。光学微调须说明意图，不以偏移掩盖父布局错误。
- **密度按任务与输入方式选**：高频桌面工具优先扫描效率，展示页可保留表达空间，触屏与易误触操作考虑更大的有效目标。已有紧凑尺寸有效时保留，不以“优化”为由整页放大；H8 的目标尺寸不等于所有控件的可见高度。可见轮廓、字号、内边距与点击区域分别决定，扩展命中区须实测且不重叠。低频内容可渐进披露，但关键任务与信息仍须可发现、可达。

## 配色推导与表面层级示例

只在配色或层级确有问题、且属于本轮目标时采用以下方法；不为满足示例重做完整色板，不改变用户指定主题。已有方案有效时保留。

1. **从内容与既有品牌出发**：先看主任务、内容密度、品牌色和业务状态色。优先保留有效色彩关系；需要调整时说明是解决阅读、操作识别还是层级问题，不按行业自动选色，也不为区别上一次产出强制换色。
2. **先组织大面积中性色**：为页面底、内容面、必要浮层确定明度与冷暖关系，再安排主次文字。可让中性色轻微带入已有品牌的色相，也可保留纯中性；不要把所有表面染成主色。分层只建到实际需要的程度，不把每层都变成卡片。
3. **再分配强调与语义**：主操作、选中态可共享品牌色家族，但用面积、明度和文字区分权重；风险、成功等沿用各自业务含义。分别选取强调色上的文字与图标颜色，不能因背景是“品牌色”就默认配白字。低强度色底适合局部提示，不替代必要文字或状态标识。
4. **在实际组合上验证**：按 H1/H2 检查文字及必要识别线索与实际背景，包含透明叠加、hover、焦点和选中态。页面已支持或用户要求浅/深主题时分别推导和验证，不直接反转色值；否则不额外开发主题切换。色板来源或 token 命名不代表对比度已合格。

下面是同一信息密集页面在不同主题下的关系示意，不是固定色值、组件外观或必备层数：

| 角色 | 浅色主题的可选处理 | 深色主题的可选处理 |
|---|---|---|
| 页面底与主要内容 | 轻微带色的浅灰底托住白色或近白内容面；已有纯白背景也可用留白分组 | 低亮度中性底托住略有明度差的内容面，避免所有区块都用亮线围住 |
| 同级分组与辅助区 | 同级内容保持接近的底色，用间距、标题或轻分隔组织；辅助说明降低面积与强调 | 同级内容不逐块提亮；辅助区保持可读，不靠继续压暗文字制造主次 |
| 需要浮起的区域 | 真有覆盖关系的菜单或浮层可用局部阴影、边界和遮挡关系表达 | 可用小范围表面提亮配合边界或阴影，不把普通信息卡都当浮层 |
| 主行动与风险 | 已有强调色集中于主行动，风险用局部语义色与文字指出 | 单独校验强调色上文字；风险不必整块高亮，避免与主行动争抢注意力 |

判断收益时看“内容是否更容易分组、重要事项是否更先被看到”，而不是颜色数量或所有表面的明度差是否都变大。若层级仍平，先复查空间、排版和强调分配，再考虑加强局部底色或边界。

## 修改后核验

保持截图参数一致，对照契约确认预期变化；覆盖长短标题、稀疏与密集数据、空/错误态、窄屏和缩放。检查首屏及页面下半部，而非仅截最漂亮的局部。边框改动须回归默认（含空输入）、hover、焦点与相关选中/禁用状态；页面支持浅/深主题时分别检查，不以默认态的轻描边替代状态核验。指标改动同时检查组内可比较性与主次，不只看重点项；密度改动记录可见尺寸与实际点击区域，确认没有无理由的整页放大或命中区重叠。

记录“区域 → 原问题 → 具体改动 → 可观察结果”，同时回归功能/文案保真及 H/G 检查。边框改动分别说明识别/合规结果与视觉噪音、轮廓一致性的变化，不把对比数值升高单独当作改善，也不隐去仍不合规的必要线索。没有可观察改善时不宣称高级感提升；评分仍按协议归因，不用 token 一致性代替审美质量。
