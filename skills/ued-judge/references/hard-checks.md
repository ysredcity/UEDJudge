# 硬性检查清单（hard-checks）

评论员做的是审美与整体体验的主观盲评，容易漏掉可量化、可机检的项目。本清单由**主控**独立执行，结果与评论员结论并列写进报告，**不影响评论员评分，也不传给评论员**。

## 判定规则

- 每项给出：`通过` / `不通过` / `无法判定`，并附证据（元素、实测数值、代码位置）。
- 只判断输入能支撑的项：仅有截图时，依赖 DOM/代码的项一律标 `无法判定`，不猜。
- 严重度：`阻断`（必须进阶段一）/ `一般`（按收益归入阶段）。
- 业务数据本身的乱码、重复记录、缺失、异常值或口径差异单列核对提示，不据此判检查失败；不因数据异常自动判 H9 缺少错误态。呈现或现有交互有独立失败证据时仍检查，数据内容不豁免 H/G 的字号、对比度、对齐与可访问性要求。

## H 组 · 合规

| # | 检查项 | 标准 | 严重度 | 判定依据 |
|---|---|---|---|---|
| H1 | 正文文字对比度 | ≥ 4.5:1（WCAG AA） | 阻断 | 截图取色或计算 CSS 色值 |
| H2 | 大字 / 必要非文字识别线索对比度 | 大字（≥18.66px 粗体或 ≥24px）≥ 3:1；识别控件、状态或理解图形所必需的非文字视觉线索与相邻颜色 ≥ 3:1；不对所有默认边框设统一门槛 | 一般 | 渲染状态与识别线索判定 + CSS 色值计算 |
| H3 | 仅靠颜色传达信息 | 状态、优先级、数据系列除颜色外还有文字 / 图标 / 形状 | 阻断 | 截图 + DOM |
| H4 | 焦点可见 | 所有可交互元素有可见的 `:focus-visible` 样式，未被 `outline: none` 裸去除 | 阻断 | 代码 |
| H5 | 键盘可达 | 关键路径上的操作可用 Tab / Enter / Space 完成，无键盘陷阱 | 阻断 | 代码 / 实测 |
| H6 | 可访问名 | 纯图标按钮有 `aria-label`；表单控件有关联 `<label>` | 一般 | 代码 |
| H7 | 最小字号 | 正文 ≥ 14px；辅助信息 ≥ 12px | 一般 | 截图 + 代码 |
| H8 | 点击目标尺寸 | 指针目标按 WCAG 2.2 SC 2.5.8 核验，通常 ≥ 24×24 CSS px；适用例外与触屏增强见细则，不规定所有控件的可见高度 | 一般 | 真实点击区域 / 相邻目标间距 / 实测 |
| H9 | 状态覆盖 | 见下方细则 | 一般 | 代码 / 实测 |
| H10 | 响应式 | 在 1440 / 1024 / 768 / 375 宽度下无横向溢出、无内容遮挡 | 一般 | 多视口截图 |
| H11 | 减弱动效 | 有动画时尊重 `prefers-reduced-motion` | 一般 | 代码 |
| H12 | 敏感信息展示 | 密钥、口令等默认遮蔽，不以明文显示在界面上 | 阻断 | 截图 + 代码 |

**H2 适用细则**（按 WCAG 2.2 SC 1.4.11 及 W3C Understanding 的边界说明区分用途）：

- 先判断当前状态下用户靠什么识别控件、操作区域或状态，再计算该线索与实际相邻颜色的对比度；不能仅扫描所有 `border`，把低于 3:1 的值一律判失败。
- 控件可由有足够对比度的填充面、可操作文字或图标识别，不必同时具有高对比描边。文字按 H1 / H2 大字要求检查，必要图标或填充面按非文字要求检查；附近的静态标签、位置与间距可辅助识别，但不能自动豁免难以辨认的输入区域。
- 必要识别线索不足时，比较填充、局部边界或其他有效线索对可发现性与视觉噪音的影响，不默认把同类控件的整圈边框统一提亮。局部线条若承担必要识别仍须达标；默认态须可发现，不能只在 hover / focus 后才显示识别线索。具体实现方法见 [visual-optimization.md](visual-optimization.md)。
- 卡片装饰描边、辅助分组线、表格分隔线若不承担必要识别或数据含义，不设 3:1 下限；分组仍须清楚。若边界是识别控件的唯一视觉线索，或线条承担必要图形含义，仍须达到 3:1。
- 焦点、选中、勾选等状态所必需的非文字指示仍按 3:1 检查，焦点可见性同时归 H4；不能用默认边框可弱化来豁免状态指示。额外 hover 装饰不必单独达到 3:1，但不能削弱已有必要线索；不要求前后两个非相邻状态色互达 3:1。
- 非活动控件、未经作者修改的用户代理外观及图形的必要特定呈现按该条的适用例外注明原因，不据此豁免其他 H 项。
- 证据写明「元素 / 状态 → 边框用途 → 实际识别线索 → 相邻颜色 → 实测值或无需独立检查边框的理由」。识别依据不清时标为「无法判定」，不自动通过；渐变、透明叠加按实际渲染检查。

**H8 适用细则**：

- 24×24 CSS px 是 SC 2.5.8 的 AA 最低目标尺寸，不是推荐的统一控件外观。目标不足尺寸时，可按间距例外核验：以其包围盒中心画直径 24 CSS px 的圆，不与其他目标或其他不足尺寸目标的该圆相交。等效目标、行内、用户代理控制、必要呈现等例外须注明适用依据，不能笼统豁免。
- 44×44 CSS px 属于 SC 2.5.5 的 AAA 增强目标，不是所有触屏控件的 AA 门槛。触屏为主要使用方式或操作易误触时，优先考虑该增强目标；仅未达 44px 不自动判 H8 失败。用户或既有设计系统明确要求该尺寸时按相应范围核验，不扩展到全端。测试窄屏不等于所有桌面控件也须放大；混合输入设备兼顾实际操作方式。
- 可见尺寸与有效点击区域分别记录；扩大真实点击区域不必同比放大字体、内边距或视觉轮廓。扩展区域须确实响应对应操作，且不与相邻目标重叠、不误触、不遮挡焦点；不能只按布局占位盒认定可点击。
- 证据包含场景 / 输入方式、可见尺寸、实际目标尺寸、相邻目标及适用例外。仅截图无法验证不可见的命中区域时标为「无法判定」，不伪造实测结果。

H10 需要额外截图，这些截图**只给主控用，不给评论员**。

H11 应同时核查 CSS 与 JS 动效，实测减弱偏好下非必要位移/缩放及平滑滚动的替代；仅阅读代码不能证明替代可用。该项是本 skill 的工程要求，不宣称 WCAG AA 包含 SC 2.3.3（该条属 AAA）。

**H9 状态覆盖细则**（任一不满足即不通过，证据写明缺哪一项）：
- 关键交互组件具备默认、悬停、焦点、按下、禁用、加载、错误各状态中与其用途相关的部分。
- 异步加载按用途提供加载反馈：已知内容结构可用与最终布局一致的骨架/占位；短操作可用保留操作含义的按钮内反馈，不强制全部改成骨架屏，也不为演示而伪造等待。大内容区不以孤立转圈代替上下文。
- 空状态说明原因并给出下一步操作，不只写"暂无数据"。
- 错误状态说明发生了什么、用户能做什么，不裸露错误码或堆栈。
- 提交、复制、删除等操作有明确的结果反馈。

## G 组 · 布局几何

| # | 检查项 | 标准 | 严重度 | 判定依据 |
|---|---|---|---|---|
| G1 | 同排控件对齐 | 同一工具栏、筛选行或表单操作行中，比较按钮与输入框的**控件本体**，默认底边对齐；明确采用中心线对齐的布局按中心线检查。不能把输入框上方的 label、提示或错误文字计入控件本体的对齐盒子。预期共同对齐线的最大偏差 ≤2 CSS px | 一般 | 默认态与相关响应式视口的 DOM 几何测量 + 截图 |

G1 执行细则：
- 先确认哪些控件在同一视觉行、采用哪条对齐线，再使用 `getBoundingClientRect()` 比较对应的 `bottom` 或垂直中心坐标；记录元素、视口与最大偏差。
- 2 CSS px 是本 skill 的工程检查容差，不是无障碍标准。字体的光学微调或有明确目的的非对称排版可以例外，须说明意图；意外错位不能借此豁免。
- 标签换行、提示/错误文字出现、加载态文本变化时，控件本体仍须保持预期对齐。响应式改成分行时，只比较各自同行的控件，不要求上下两行有同一底边。
- 仅有截图时可标记肉眼可见的错位，不伪造 CSS px 测量；需要精确值却没有 DOM 时标为「无法判定」。
- 修复示例：按钮组与带上方标签的搜索输入并排时，可使父容器按底边对齐（如 `align-items: flex-end`），或把标签放在独立的网格行。完成后重新测量，不靠负 margin 或逐像素偏移掩盖问题。

## A 组 · 可机检反模式

源码用于定位疑似模式，再按下表的用途与判定条件确认；确认命中后记为不通过，严重度均为 `一般`，同时在 glossary 中归为「AI 感套路」。有任务用途的分组或比较结构，不因外观相似就自动判失败。

| # | 反模式 | 判定标准 | 常见替代做法 |
|---|---|---|---|
| A1 | 单侧彩色边框 | 卡片、列表项、提示框使用 >1px 的 `border-left` / `border-right`，或等效的 `box-shadow: inset` / 伪元素竖条作为彩色强调 | 完整描边、背景色块、前置图标或编号，或不加 |
| A2 | 渐变文字 | `background-clip: text` 配合渐变背景 | 单一实色，靠字重或字号强调 |
| A3 | 装饰性玻璃拟态 | `backdrop-filter: blur` 用在没有覆盖关系的普通卡片上 | 实色表面；仅在浮层确需透出底层时使用 |
| A4 | 英雄指标模板 | 一个超大数字 + 小标签 + 若干辅助数字 + 渐变或光晕强调，作为页面首屏主体 | 按任务组织信息，指标服从结论 |
| A5 | 无目的卡片嵌套 | 重复套框没有新增分组、状态或操作含义，反而增加边界噪音；有语义的区域与子项层级不自动命中 | 去除无作用的一层，保留必要分组；可用间距、标题或轻分隔 |
| A6 | 无目的同质卡片网格 | 3 个及以上同款「图标 + 标题 + 文字」卡片平铺，且无比较/分组用途或造成主次不清；用于扫描比较的指标组不因同形、等大自动命中 | 保留比较所需的一致性，用分组或局部强调建立主次，不强制改变尺寸或拆散容器 |
| A7 | 弹窗优先 | 能在当前页面内联完成的操作使用模态弹窗 | 内联展开、侧边面板、渐进披露 |

按上表检查可读取的源码与渲染结果；仅有截图时，无法从截图确认的实现细节标为「无法判定」。检查结果只进入主控报告，不传给评论员。

## L 组 · 认知负荷计数

以下只列能计数或能直接判断的认知负荷项。每项通过 / 不通过：

| # | 检查项 | 标准 |
|---|---|---|
| L1 | 单一主焦点 | 首屏能指出唯一的主焦点，没有两个及以上同等权重的元素在争抢 |
| L2 | 首屏指标有主次 | 看板类界面首屏核心指标 ≤ 4 个即通过；超过 4 个时，须有 1–2 个主指标在字号或表面上明显突出，或按主题分组。仅数量超出、但主次清楚不判失败 |
| L3 | 决策点选项数 | 任一决策点同时可见的选项或操作 ≤ 4 个；主操作每组只有 1 个 |
| L4 | 分组内有扫读引导 | 每个视觉分组内并列条目 ≤ 4 个即通过；超过时，须有二级分组、排序、折叠或视觉主次中的任一种。条目多但扫读有引导不判失败 |
| L5 | 渐进披露 | 低频内容（配置、长尾条目、高级选项）默认收起 |
| L6 | 避免无目的重复展示 | 界面组织不制造无任务作用的重复；摘要、详情、编辑与导出各有用途时允许重复。源数据中的重复记录不据此判失败 |
| L7 | 免记忆 | 完成当前决策所需的信息在同一屏可见，不需要记住别处的内容 |
| L8 | 模式一致 | 同类操作在不同位置的样式和行为一致 |

按不通过项数分级：0–1 项为低负荷；2–3 项为中负荷，按收益归入阶段；4 项及以上为高负荷，整组按 `阻断` 处理并进阶段一。

L 组修复不得以删除功能、字段或业务信息为手段（见 [execution-constraints.md](execution-constraints.md) X5）；优先用分组、排序、主次与渐进披露解决。
