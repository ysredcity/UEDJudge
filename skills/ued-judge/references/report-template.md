# 报告模板（report-template）

三份报告均**在对话中输出**，不写文件；用户要求保存时再写到用户指定位置（默认当前工作目录）。评论员与核验员的原话可精炼，但**判定、分数、审美方向、差距条目及其维度与严重度标注、做得好的地方，含义都不得改动**。

数据核对提示与界面差距分列：只提示、不计分，不占差距名额，不自动进入 UI 优化阶段。报告记录整体 skill 版本（取自 SKILL.md 的 metadata.version）、评分口径版本与评委模型；整体版本与评分口径独立，阶段简报沿用同一流程的记录。历史分数不回填，跨评分口径版本不计算优化增益。

## 呈现原则：默认摘要，依据保留

- **只压缩交付，不压缩工作**：双样本、完整 G 清单及原话、逐项检查、阶段动作与目标、保护/保真清单、逐条收尾核验均照常完成，保留在本轮主控记录中。下方完整依据模板用于组织这些记录，不要求每次全部贴进对话；用户要详情时直接提供已有依据，不重新调用评委。普通版不为精简自动写报告文件；Pro 按交付协议保留完整报告与原始评语。
- **默认输出下方摘要模板**；同一事实只讲一次，用 G/H 等编号串联问题、阶段和核验。不重复使用途径五项、逐维度评分表、已通过检查长表、同一保护清单或评委原文。元数据合为一行，审美方向/保护要点合为一句；详情按需查看。
- **不得藏进详情的信息**：所有 P0/P1、阻断项、真退步、未达成原因、影响结论/执行的未知项与覆盖不足、需单独授权或不在本轮范围的问题；评分不稳定、标签错位、依据越界、格式不完整等异常仍提示。数据提示独立不计分。不能机械截成“前 3 条”、遗漏差距或把部分解决写成已解决。
- **推荐不等于选择**：具备优化能力且有可执行阶段时，优先推荐按顺序一次性执行本轮全部阶段，注明每阶段仍自检、最后统一复评与核验；阶段数按实际 1–3 个生成，不固定为“两阶段”。保留逐阶段、只要报告和指定阶段的选择，用户确认前停下。仅截图、无源码写权限或无可执行阶段时不推荐执行，说明原因。

## A. 诊断报告（Step 6）

### 默认摘要

```markdown
# UED 诊断 · <对象>
<对象/输入与能力边界> · Skill <版本> · 口径 <版本> · 评委 <模型或未知>

结论：<主要体验问题与可改善范围，1–2 句>。参考评分：双样本 <a/b>，平均 <x>/24；<不稳定/覆盖等异常，无则省略>。
方向与保留：<审美方向、已有优点及功能/文案保护要点；有分歧不强行合并>。

## 关键问题与执行边界
- <G/H 等编号 · 项号/严重度/置信度或检查结果 · 具体问题与简短证据>
- <未展示的低优先问题仅汇总数量；完整条目保留在依据中，P0/P1、阻断与关键未知项全部列出>
- <数据核对提示（不计分）、单独授权项、无法验证范围；确无则合为“无额外数据/授权边界”>

## 优化方案
| 阶段 | 对应问题 | 具体动作与可观察目标 |
|---|---|---|
| 一 · <名称> | G1/H1… | <合并写动作和验收目标，不复述整段问题> |
| 二 · <名称> | … | … |

## 下一步
1. 推荐：一次性执行以上<N>个阶段（逐阶段自检，最后统一复评与核验）
2. 逐阶段执行（每阶段成对复评，按结果调整后续阶段）
3. 只要报告，到此为止

也可指定阶段。详细评分、完整问题与检查证据可按需查看；选择执行后先写目标稿，再动手。
```

不能执行时，替换上述执行选项为「本次仅出报告：<原因>」，不展示可执行推荐。不要因为摘要减少阶段内实际动作或跳过任一检查。

写法要求：
- 「具体改动」写到元素、数值、做法，不写「优化视觉层次」这种空话。
- 每条改动都要能对应到一条 G 编号差距、一个高置信缺口或一个硬性检查编号。
- 「目标状态」写成截图上能看出来的结果，如「红色只出现在 P0 与超期两处」。
- 阶段只有 1 个或 2 个时，删掉多余的阶段小节。

## B. 阶段复评简报（逐阶段执行时，每阶段后）

```markdown

  | D | 旧版更好 | 低 | 否（指向未改动的日报区） | 噪声 |
  | … | | | | |

- 新版独有问题（评论员正文 B 第 3 步）：<无 / 条目〔指向本轮改动 / 指向未改动元素〕>
```

判定列只填：`真实改进`、`倾向改进`、`真退步（建议回退）`、`噪声`、`持平`，按 critic-protocol Step 7「维度判定规则」执行。

## C. 收尾报告（Step 8）

### 默认摘要

```markdown

## 验证与交付
```
