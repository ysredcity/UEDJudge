# 报告模板（report-template）

三份报告均**在对话中输出**，不写文件；用户要求保存时再写到用户指定位置（默认当前工作目录）。评论员与核验员的原话可精炼，但**判定、分数、审美方向、差距条目及其维度与严重度标注、做得好的地方，含义都不得改动**。

数据核对提示与界面差距分列：只提示、不计分，不占差距名额，不自动进入 UI 优化阶段。每份报告记录评分口径版本与评委模型；历史分数不回填，跨版本不计算优化增益。

---

## A. 诊断报告（Step 6）

```markdown
# UED 诊断报告 · <评估对象名称>

## 1. 概述
- 评估对象：<URL / 文件路径 / 截图>
- 评分口径：<冻结 prompt 版本，如 v3.1>；评委模型：<模型或子智能体类型>
- 输入类型：<URL | 本地 HTML | 工程 | 仅截图>　→ 可执行优化：<是 / 否（原因）>
- 截图：总览 + <n> 张切片<；未覆盖区域：…（切片被截断时）>
- 使用途径：
  - 界面类型：<任务型工具 | 品牌展示>
  - 用户：…
  - 场景：…
  - 核心任务：…
  - 关键路径：…

## 2. 评论员结论（盲评双样本）
- 审美方向：<两样本一致时写一条；不一致时分别写>
- 顶尖水准设想：…（3–5 句，合并精炼）
- 合并差距清单（G 编号用于收尾核验）：
  | 编号 | 差距（评论员原话） | 项号 · 严重度 | 置信度 |
  |---|---|---|---|
  | G1 | … | B3 · P1 | 高（两样本都提到） |
  | G2 | … | C3 · P2 | 低（仅样本 2） |
- 做得好的地方：
  - …
- 维度评分：

  | 维度 | 样本 1 | 样本 2 | 平均 | 高置信缺口（两样本都不满足的项） |
  |---|---|---|---|---|
  | A 构图与视觉层级 | x | x | x | A3 留白节奏单一 |
  | B 信息组织与认知负荷 | x | x | x | … |
  | C 色彩与语义 | x | x | x | … |
  | D 字体与数据排版 | x | x | x | … |
  | E 一致性与去模板化 | x | x | x | … |
  | F 任务效率与状态可见性 | x | x | x | … |
  | **合计** | a / 24 | b / 24 | **(a+b)/2 / 24**，换算 **Y / 10** | |

  <同一维度两样本相差 ≥2 时注明「X 维度评分不稳定」>

- 数据核对提示（不计分，不进入 UI 阶段；无则写无）：
  - … [数据 · 不计分]

## 3. 硬性检查
| # | 检查项 | 结果 | 证据 |
|---|---|---|---|
| H1 | 正文对比度 | 不通过 | （示例）`.hint` 文字色 / 背景色 实测 3.8:1 |
（H、G、A 组只列「不通过」与「无法判定」；其余汇总为「其余 N 项通过」。G1 写明控件、对齐线、视口和实测偏差。）

- 认知负荷（L 组）：<N> 项不通过 → <低 / 中 / 高>负荷；不通过项：…
- Web / 动效补充（W / M 组）：<适用项结果与证据；不适用原因；无法判定项>

## 4. 保护清单与保真清单
视觉保护清单（来自评论员「做得好的地方」，改动不得削弱）：
- …

功能与文案保真清单（主控）：
- 受影响的原有功能入口 / 关键状态 / 操作结果：…
- 须保留的描述及业务含义：…
- 无法验证的项：…（其余原有功能与描述仍默认保留）

## 5. 可改善上限
- UI 可解决（已进入下方阶段）：G1、G3、H1 …
- 依赖数据核对（只提示，不进阶段）：…
- 需要功能或语义变更授权（未进入阶段，待你单独决定）：…

## 6. 改进方案
### 阶段一 · 必做
| 对应问题 | 严重度 / 置信度 | 标签 | 具体改动 | 目标状态（可观察，尽量对应勾选项） |
|---|---|---|---|---|
| G1 | P1 / 高 | 内容组织 | … | B2 满足：风险区并入清单作为行状态，不再单独重复 |
| H1 | 阻断 | 合规·H1 | … | 辅助文字对比度 ≥4.5:1 |

### 阶段二 · 重要
…

### 阶段三 · 可选
…

## 7. 下一步（请选择）
1. 只要报告，到此为止
2. 逐阶段执行（每阶段后成对复评并动态调整；子智能体调用 ≤ 7 次）
3. 按顺序一次性执行全部阶段（最后统一复评；子智能体调用 5 次）

也可以只执行指定阶段，例如「只做阶段一」。选择执行后，我会先写目标设计稿再动手，不再额外停下确认。
```

写法要求：
- 「具体改动」写到元素、数值、做法，不写「优化视觉层次」这种空话。
- 每条改动都要能对应到一条 G 编号差距、一个高置信缺口或一个硬性检查编号。
- 「目标状态」写成截图上能看出来的结果，如「红色只出现在 P0 与超期两处」。
- 阶段只有 1 个或 2 个时，删掉多余的阶段小节。

## B. 阶段复评简报（逐阶段执行时，每阶段后）

```markdown
## 阶段 <n> 完成 · 复评

- 本阶段改动：<3–5 条，文件与要点>
- 主控自检：<目标状态逐条：达成 / 未达成（原因）；自检轮数；发现并已修正的新问题>
- 成对复评（上一保留版本 vs 本阶段版本；随机分配：新=<A/B>）：

  | 维度 | 结果（还原后） | 把握 | 依据是否指向本轮改动 | 判定 |
  |---|---|---|---|---|
  | A | 新版更好 | 高 | 是（风险区并入清单） | 真实改进 |
  | C | 持平 | — | — | 持平 |
  | D | 旧版更好 | 低 | 否（指向未改动的日报区） | 噪声 |
  | … | | | | |

- 新版独有问题（评论员正文 B 第 3 步）：<无 / 条目〔指向本轮改动 / 指向未改动元素〕>
- 数据核对提示：<无 / …>
- 保护清单：<完好 / 被削弱的项及原因>
- 保真核验：<受影响功能的回归结果与证据；无法验证项>
- 文案变化：<未改 / 原文 → 新文案 → 原意保持依据>
- 硬性检查变化：<H1 不通过 → 通过 …>
- Web / 动效验证：<W/M 受影响项结果与证据>
- 后续阶段调整：<保持不变 / 调整内容（原因）>
```

判定列只填：`真实改进`、`倾向改进`、`真退步（建议回退）`、`噪声`、`持平`，按 critic-protocol Step 7「维度判定规则」执行。

## C. 收尾报告（Step 8）

```markdown
# UED 优化收尾 · <评估对象名称>

- 执行方式：<逐阶段 / 一次性 / 仅阶段 x>
- 评分口径：<v3.1>；评委模型：<…>
- 务实目标：<达成 / 未达成>
  | 条件 | 结果 |
  |---|---|
  | 初评 P0/P1 差距全部「已解决」（可改善上限 ②③ 除外） | <是 / 否：G2 部分解决> |
  | 成对比较无维度「真退步」 | <是 / 否：…> |
  | 收尾绝对样本无 P0/P1、每维度 ≥3 | <是 / 否：…> |
  | 保真核验无未授权遗漏或语义漂移 | <是 / 否：…> |

- 差距核验（核验员）：已解决 n / 部分解决 n / 未解决 n / 无法判断 n → 解决率 <x%>
  | 编号 | 差距 | 判定 | 改版后证据 |
  |---|---|---|---|
  | G1 | … | 已解决 | … |
  核验员发现的新问题：<无 / …>

- 成对比较：<一次性：初始 vs 最终逐维度结果；逐阶段：各维度判定链，如 A：改进 → 持平 → 改进>
- 评分轨迹（仅参考）：初评双样本平均 <x / 24（Y / 10）> → 收尾单样本 <z / 24（W / 10）>；顶尖参考线：<接近 / 未接近>
  | 维度 | 初评平均 | 收尾 |
  |---|---|---|
  | A | … | … |
- 完成情况：
  | 阶段 | 状态 | 要点 |
  |---|---|---|
  | 阶段一 | 已完成 | … |
- 保护清单：<全部完好 / 变动项及原因>
- 功能与文案保真：<已核验范围、结果与证据；无法验证项；明确授权的变化（无则写无）>
- 硬性检查：修复前 N 项不通过 → 修复后 M 项不通过；认知负荷 <中 → 低>
- Web / 动效验证：<W/M 适用项变化与证据>
- 剩余差距（优先列核验为未解决/部分解决的高置信条目，再列收尾样本新提出的）：
  1. … [项号 · 严重度]
- 可改善上限：<依赖数据核对的项；需要功能或语义授权的项>
- 建议：<如未达成，是否另起一轮新诊断>
- 临时文件：`./.ued-judge/`（截图、目标稿与备份），是否删除？
```
