# 报告模板（report-template）

三份报告均**在对话中输出**，不写文件；用户要求保存时再写到用户指定位置（默认当前工作目录）。评论员的原话可精炼，但**评分、审美方向、差距条目的含义不得改动**。

---

## A. 诊断报告（Step 6）

```markdown
# UED 诊断报告 · <评估对象名称>

## 1. 概述
- 评估对象：<URL / 文件路径 / 截图>
- 输入类型：<URL | 本地 HTML | 工程 | 仅截图>　→ 可执行优化：<是 / 否（原因）>
- 使用途径：
  - 用户：…
  - 场景：…
  - 核心任务：…
  - 关键路径：…

## 2. 评论员结论（盲评）
- 审美方向：…
- 顶尖水准设想：…（3–5 句，精炼）
- 差距清单（按严重度）：
  1. …
  2. …
- 评分：**X / 10**

## 3. 硬性检查
| # | 检查项 | 结果 | 证据 |
|---|---|---|---|
| H1 | 正文对比度 | 不通过 | （示例）`.hint` 文字色 / 背景色 实测 3.8:1 |
（只列「不通过」与「无法判定」；其余汇总为「其余 N 项通过」）

## 4. 改进方案
### 阶段一 · P0 必做
| 对应问题 | 标签 | 具体改动 | 预期效果 |
|---|---|---|---|
| 差距 1 | 构图 | … | … |
| H1 | 合规·H1 | … | … |

### 阶段二 · P1 重要
…

### 阶段三 · P2 可选
…

## 5. 下一步（请选择）
1. 只要报告，到此为止
2. 逐阶段执行（每阶段后复评并动态调整，评论员调用 ≤ 4 次）
3. 按顺序一次性执行全部阶段（最后统一复评，评论员调用 2 次）

也可以只执行指定阶段，例如「只做阶段一」。
```

写法要求：
- 「具体改动」写到元素、数值、做法，不写「优化视觉层次」这种空话。
- 每条改动都要能对应到一条差距或一个硬性检查编号。
- 阶段只有 1 个或 2 个时，删掉多余的阶段小节。

---

## B. 阶段复评简报（逐阶段执行时，每阶段后）

```markdown
## 阶段 <n> 完成 · 复评

- 本阶段改动：<3–5 条，文件与要点>
- 评分：<上次> → **<本次> / 10**
- 评论员本次差距清单：
  1. …
- 硬性检查变化：<H1 不通过 → 通过；新增不通过 …>
- 后续阶段调整：<保持不变 / 调整内容（原因）>
- 退化提示（如有）：<分数下降原因判断 + 回退或保留建议>
```

---

## C. 收尾报告（Step 8）

```markdown
# UED 优化收尾 · <评估对象名称>

- 执行方式：<逐阶段 / 一次性 / 仅阶段 x>
- 评分轨迹：X → Y（→ Z …）/ 10　<已达 9 分参考线 / 未达线>
- 完成情况：
  | 阶段 | 状态 | 要点 |
  |---|---|---|
  | 阶段一 | 已完成 | … |
- 硬性检查：修复前 N 项不通过 → 修复后 M 项不通过
- 剩余差距（来自最后一次评论员结论）：
  1. …
- 建议：<如未达线，是否另起一轮新诊断>
- 临时文件：`./.ued-judge/`（截图与备份），是否删除？
```
