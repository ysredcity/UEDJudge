# 报告模板（report-template）

三份报告均**在对话中输出**，不写文件；用户要求保存时再写到用户指定位置（默认当前工作目录）。评论员的原话可精炼，但**分数、审美方向、差距条目及其维度与严重度标注、做得好的地方，含义都不得改动**。

---

## A. 诊断报告（Step 6）

```markdown
# UED 诊断报告 · <评估对象名称>

## 1. 概述
- 评估对象：<URL / 文件路径 / 截图>
- 输入类型：<URL | 本地 HTML | 工程 | 仅截图>　→ 可执行优化：<是 / 否（原因）>
- 使用途径：
  - 界面类型：<任务型工具 | 品牌展示>
  - 用户：…
  - 场景：…
  - 核心任务：…
  - 关键路径：…

## 2. 评论员结论（盲评）
- 审美方向：…
- 顶尖水准设想：…（3–5 句，精炼）
- 差距清单（按严重度）：
  1. … [B · P1]
  2. … [C · P2]
- 做得好的地方：
  - …
- 维度评分：

  | 维度 | 分数 | 依据 |
  |---|---|---|
  | A 构图与视觉层级 | x / 4 | … |
  | B 信息组织与认知负荷 | x / 4 | … |
  | C 色彩与语义纪律 | x / 4 | … |
  | D 字体与数据排版 | x / 4 | … |
  | E 一致性与去模板化 | x / 4 | … |
  | F 任务效率与状态可见性 | x / 4 | … |
  | **合计** | **X / 24** | 换算 **Y / 10** |

## 3. 硬性检查
| # | 检查项 | 结果 | 证据 |
|---|---|---|---|
| H1 | 正文对比度 | 不通过 | （示例）`.hint` 文字色 / 背景色 实测 3.8:1 |
| A1 | 单侧彩色边框 | 不通过 | （示例）`.risk-card` `border-left: 3px` |
（H 组、G 组、A 组只列「不通过」与「无法判定」；其余汇总为「其余 N 项通过」。G1 写明控件、对齐线、视口和实测偏差；仅截图时注明估计。）

- 认知负荷（L 组）：<N> 项不通过 → <低 / 中 / 高>负荷；不通过项：L2、L6 …
- Web / 动效补充（W / M 组）：<适用项结果与证据；不适用原因；无法判定项>。与 H/G 重叠引用原编号，不重复计数；静态截图不能判断动效时序与流畅性。

## 4. 保护清单
改动过程中不得削弱以下元素（来自评论员「做得好的地方」）：
- …

功能与文案保真清单（主控，独立于视觉保护清单）：
- 受影响的原有功能入口 / 关键状态 / 操作结果：…
- 须保留的描述及业务含义：…
- 无法验证的项：…（其余原有功能与描述仍默认保留）

## 5. 改进方案
### 阶段一 · 必做
| 对应问题 | 严重度 | 标签 | 具体改动 | 预期效果 |
|---|---|---|---|---|
| 差距 1 | P1 | 内容组织 | … | … |
| H1 | 阻断 | 合规·H1 | … | … |

### 阶段二 · 重要
…

### 阶段三 · 可选
…

涉及视觉时附简短设计契约（焦点、字体/色彩角色、表面层级、密度）；涉及动效时附“触发 → 状态变化 → 属性/时长/缓动 → 打断/减弱替代”。只填写本轮相关内容，不强制添加动效或第三阶段。

## 6. 下一步（请选择）
1. 只要报告，到此为止
2. 逐阶段执行（每阶段后复评并动态调整，评论员调用 ≤ 5 次）
3. 按顺序一次性执行全部阶段（最后统一复评，评论员调用 3 次）

也可以只执行指定阶段，例如「只做阶段一」。
```

写法要求：
- 「具体改动」写到元素、数值、做法，不写「优化视觉层次」这种空话。
- 每条改动都要能对应到一条差距或一个硬性检查编号。
- 「预期效果」写成可验证的方向，如「红色只出现在 P0 与超期两处」。
- 阶段只有 1 个或 2 个时，删掉多余的阶段小节。

---

## B. 阶段复评简报（逐阶段执行时，每阶段后）

```markdown
## 阶段 <n> 完成 · 复评

- 本阶段改动：<3–5 条，文件与要点>
- 维度分变化：

  | 维度 | 上次 | 本次 | 变化 | 判定 |
  |---|---|---|---|---|
  | A | 3 | 3 | 0 | — |
  | B | 2 | 4 | +2 | 真实改进（差距 1 已消失，对应本轮改动） |
  | C | 2 | 1 | −1 | 噪声 |
  | … | | | | |
  | 合计 | 15 | 17 | 换算 6.3 → 7.1（仅供参考） | |

- 评论员本次差距清单（标注归因）：
  1. … [维度 · 严重度]〔指向本轮改动 / 指向未改动元素〕
- 保护清单：<完好 / 被削弱的项及原因>
- 保真核验：<受影响功能的回归结果与证据；无法验证项>
- 文案变化：<未改 / 原文 → 新文案 → 原意保持依据；功能删减或语义变化的单独授权>
- 硬性检查变化：<H1 不通过 → 通过；A1 新增不通过 …>
- Web / 动效验证：<W/M 受影响项结果、实际交互/时序证据与能力边界；不重复计 H/G，不改变盲评分数>
- 后续阶段调整：<保持不变 / 调整内容（原因）>
```

判定列只填三种：`真实改进`、`真退步（建议回退）`、`噪声`，按 critic-protocol Step 7「分数变化判定」执行。

---

## C. 收尾报告（Step 8）

```markdown
# UED 优化收尾 · <评估对象名称>

- 执行方式：<逐阶段 / 一次性 / 仅阶段 x>
- 评分轨迹（换算 10 分制）：X → Y（→ Z …）
- 收尾双样本：

  | 维度 | 样本 1 | 样本 2 | 平均 |
  |---|---|---|---|
  | A | … | … | … |
  | … | | | |
  | 合计 | a / 24 | b / 24 | 定论 **(a+b)/2 / 24**，换算 **Y / 10** |

  较低换算分 <min> → <已达 9 分参考线 / 未达线>；<有维度两次相差 ≥2 分时注明「X 维度评分不稳定」>
- 完成情况：
  | 阶段 | 状态 | 要点 |
  |---|---|---|
  | 阶段一 | 已完成 | … |
- 保护清单：<全部完好 / 变动项及原因>
- 功能与文案保真：<已核验范围、结果与证据；无法验证项；明确授权的功能或语义变化（无则写无）>
- 硬性检查：修复前 N 项不通过 → 修复后 M 项不通过；认知负荷 <中 → 低>
- Web / 动效验证：<W/M 适用项变化、实测证据或无法判定；视觉契约实现情况；没有实测不宣称动效流畅或跨平台通过>
- 剩余差距（优先列两个样本都出现的条目）：
  1. … [维度 · 严重度]
- 建议：<如未达线，是否另起一轮新诊断>
- 临时文件：`./.ued-judge/`（截图与备份），是否删除？
```
