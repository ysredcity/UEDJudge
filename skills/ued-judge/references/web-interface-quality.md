## W 组 · 工程检查

| # | 适用场景与要求 | 如何验证 |
|---|---|---|
| W1 | 交互语义与焦点：导航使用真实链接，操作使用按钮；浮层按其类型管理进入/返回焦点，固定区域不遮住焦点；手势操作有按钮/键盘替代 | 键盘走关键路径、关闭浮层、打开链接；焦点与键盘失败归 H4/H5，避免重复计数 |
| W2 | 输入完整性：允许粘贴、输入法组合、密码管理器及浏览器缩放；保留编辑内容。校验在字段附近说明，并让用户找到首个错误 | 粘贴、中文输入、校验失败、缩放及重渲染后检查值/焦点；仅在原有流程确有提交时保留其 Enter 约定，不给 textarea 擅自新增提交行为 |
| W3 | 异步与恢复：结果提示可被辅助技术感知；处理重复提交、失败恢复、草稿丢失及危险操作确认/撤销；loading 不改变操作承诺 | 成功/失败/连续点击/离开实测。请求去重按既有后端能力，不伪造幂等保证；缺失关键状态归 H9 |
| W4 | 内容与布局韧性：长标题、长标识、缺失值、稀疏/密集内容不互相遮挡；图片与占位预留空间；锚点目标不被固定区盖住 | 多视口、长短内容、加载前后与缩放实测；允许表格局部滚动，不把它误报为页面溢出。响应式问题归 H10，对齐归 G1 |
| W5 | 导航上下文：已有筛选/分页/标签页若需分享、刷新或返回恢复，则核查 URL/历史及滚动恢复 | 仅同步非敏感、可分享状态；密钥和私密草稿不进 URL。未有该产品需求时不把所有 UI 状态深链接化 |
| W6 | 性能与资源：输入响应不被昂贵渲染拖慢，图片/长列表资源按需要加载，DOM 测量读写不交错造成反复布局 | 对相关设备/浏览器测量；只有确有瓶颈才增加虚拟化或新方案，保留查找、焦点及可访问性。没有测量能力标无法判定，不承诺统一接口时限 |

每项报告 `通过 / 不通过 / 无法判定`，附实际操作、元素或测量证据。聚合项不通过须指明缺失子项；注明与 H/G 重叠的归属。W 组发现的真实阻塞按业务影响进入既有阶段，不因来源名自动升级为“合规阻断”。

## 按需采用的打磨建议

- 图标与文字平衡视觉重量，数据比较用等宽数字；单位/快捷键避免无意义断行，格式符合用户语言与业务时区，不猜统计口径。
- 内联说明优于把必要信息塞进 tooltip；tooltip 不成为唯一可达的说明方式。
- 短操作避免加载提示闪烁，可延迟显示指示器；响应已经完成就立即允许继续，不为了最短动画播放时间拖延用户。
- 移动输入字体可采用至少 16px 避免部分浏览器自动放大，但不禁用用户缩放；原文、密码和标识不因“清理空白”或自动翻译而改变。
- 对刘海安全区、始终显示滚动条、原生 select 配色、触屏 hover 缺失等问题，在相关目标平台验证；未经实测不宣称跨平台通过。

这些建议不是统一外观模板，不强制更换字体、为所有按钮添加缩放、把所有加载改为骨架屏，或添加无产品需求的快捷键。动效执行与验证见 [motion-optimization.md](motion-optimization.md)。
