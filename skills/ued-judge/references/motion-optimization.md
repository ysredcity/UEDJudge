# 微动效执行与验证（主控）

用于已有界面的操作反馈、内容披露和状态过渡。Step 4 检查关键路径，Step 5 将有收益的动效归入既有阶段，Step 7 实施后验证。没有合适机会时不添加动画；用户要求无动效时遵从。

## 设计状态，不堆效果

每个拟改动的交互记录：`触发 → 前后状态 → 要解释的变化 → 属性/时长/缓动 → 连续操作时的处理 → 减弱动效替代`。

- 任务型工具以轻量反馈为主：按下、展开收起、生成/复制结果、目标定位。不得为动画延迟真实结果、编造加载过程、隐藏初始内容或改变提交语义。
- 品牌展示可在明确位置增加表达型动效，但不要把整页错峰入场、视差或持续漂浮作为默认；不劫持浏览器滚动。
- 同类状态变化采用一致节奏；同一时刻保持清楚的注意力中心，不让多处运动竞争。
- 动效补充而非替代文字、焦点或状态提示。无动画时功能与结果仍完整。

## 参数是起点，不是合规阈值

| 用途 | 起始时长 | 选择方式 |
|---|---|---|
| hover / press 等轻反馈 | 50–150ms | 快速、低幅度；无需运动时只改变颜色/边界 |
| 内容出现、菜单或小面板 | 150–250ms | 到达常用减速曲线，运动起点与触发位置关联 |
| 较大面板或空间重排 | 250–400ms | 按尺寸与距离调整；高频操作进一步缩短 |

进入可使用 `cubic-bezier(0, 0, 0.38, 0.9)`，持续变形/重排可使用 `cubic-bezier(0.2, 0, 0.38, 0.9)`，退出可使用 `cubic-bezier(0.2, 0, 1, 0.9)` 作为任务型起点。优先已有 motion token；没有体系时仅建立必要的语义 token。弹性不是普遍违规，任务型操作避免明显过冲，表达型使用须有目的并验证。

简单过渡优先 CSS，程序化控制可用 Web Animations API；复杂协调才考虑已有动画库，不为几个按钮引入新依赖。明确列出过渡属性，不使用 `transition: all`。运动优先 transform/opacity；展开收起确需布局变化时限制范围并测量，不宣称这些属性天然保证流畅。

## M 组 · 动效工程检查

仅检查适用项，逐项写 `通过 / 不通过 / 无法判定` 与证据；没有相关行为时标明“不适用”，不计失败。M 组不计入 L 负荷计数或评论员分数，也不是 WCAG 等级认证。

| # | 检查 | 证据要求 |
|---|---|---|
| M1 | 状态与因果一致 | 实测操作、反馈及最终状态对应；无伪加载、无为播放动画而等待 |
| M2 | 可打断与可连续操作 | 快速展开/收起、重复点击、切换或离开后不出现过期反馈、错位或丢输入；动画取消不等于业务请求已取消 |
| M3 | 属性与布局稳定 | 代码明确过渡属性；实测加载/切换无意外跳动，运动起点合理；布局动画有性能证据 |
| M4 | 减弱动效与无障碍 | CSS 与 JS 均响应减弱偏好；关闭非必要位移/缩放和自动平滑滚动后，焦点、文字与状态反馈仍有效。减弱动效结果归入 H11，不重复计失败 |
| M5 | 实际流畅性 | 相关浏览器与设备实测，必要时性能记录或节流；只有代码/截图时不能宣称稳定帧率 |

验证正常、快速连续操作、失败恢复和减弱动效；涉及长列表或复杂效果时检查低性能场景。短录屏或时序实测用于主控证据；**静态截图无法判断时长、缓动、打断与帧率**。不能据此给动效打分或证明其不存在，也不能将录屏、代码或主控结论送给现有冻结评论员。若要改变评论员输入/评分，须另行明确授权与版本化。
