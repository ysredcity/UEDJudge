# 问题归类词汇表（glossary）

主控在 Step 5 归纳阶段时，给每条差距打**一个主标签**，让报告用词统一，也用于判断依赖顺序。本表**不参与打分，也不提供给评论员**。

## 标签与层级

层级决定默认先后：**结构层 → 系统层 → 表层**。同一阶段内可混合，但结构层问题不得排在表层问题之后的阶段。

| 标签 | 层级 | 含义 |
|---|---|---|
| 构图 | 结构层 | 版面布局、区块关系、视觉重心、网格 |
| 信息层级 | 结构层 | 主次关系、阅读顺序、首屏信息优先级 |
| 内容组织 | 结构层 | 信息的分组、归并、取舍、重复 |
| 字体体系 | 系统层 | 字体选择、字号阶、字重、行高 |
| 色彩体系 | 系统层 | 主色、语义色、中性色、对比关系 |
| 空间节奏 | 系统层 | 留白、间距刻度、密度 |
| 组件一致性 | 系统层 | 同类元素样式与行为是否统一 |
| 布局对齐 | 系统层 | 同排控件本体按预期底边或中心线对齐，标签/提示高度不造成错位；对应硬性检查 G1 |
| 交互反馈 | 表层 | 悬停、点击、加载、过渡、状态变化 |
| 文案 | 表层 | 标签、说明、空状态、错误提示的措辞 |
| 装饰 | 表层 | 图标、插图、纹理、分隔等辅助视觉 |
| AI 感套路 | 按所涉层级 | 见下方清单；标签后注明所涉层级，如「AI 感套路·色彩体系」 |
| 合规 | 按所涉层级 | 硬性检查不通过项，注明检查编号，如「合规·H1」「合规·A1」「合规·L6」 |

## 评论员维度与标签的对应

评论员差距条目带 `[项号 · 严重度]`（v3.1 起，如 `[C3 · P2]`，项号首字母即维度），勾选缺口也用项号，归纳时按下表对应到标签，便于判断层级先后：

| 评论员维度 | 通常对应的标签 |
|---|---|
| A 构图与视觉层级 | 构图、信息层级、空间节奏 |
| B 信息组织与认知负荷 | 内容组织、信息层级 |
| C 色彩与语义 | 色彩体系 |
| D 字体与数据排版 | 字体体系 |
| E 一致性与去模板化 | 组件一致性、装饰、AI 感套路 |
| F 任务效率与状态可见性 | 交互反馈、信息层级、文案 |

评论员给的维度与本表不一致时，以条目内容为准重新打标签，但不改动评论员的原始标注。

## 界面类型与判定口径

使用途径首行的「界面类型」决定"AI 生成感"按哪套口径判断（写进了冻结 prompt，这里供主控归纳时对照）：

| 界面类型 | 什么算好 | 要警惕什么 |
|---|---|---|
| 任务型工具 | 熟悉、克制、符合同类优秀工具的惯例；工具隐没在任务里 | 没有目的的装饰、别扭的非标准控件、模板化装饰堆砌、自造交互 |
| 品牌展示 | 有明确主张和辨识度，与同类页面能区分开 | 平庸、同质化审美、模板化构图（居中堆叠 + 同款卡片） |

同一条差距在两种类型下的处理可能相反。例如"克制的深色开发者工具风"在任务型工具里不是问题，在品牌展示页里可能就是"与同类无法区分"。

## 色彩优化口径

- **品牌色 / 主操作色**：提供辨识度并引导操作，可贯穿按钮、选中态、进度等相关元素；多处复用不等于语义混乱。
- **语义色**：表达成功、风险、错误等状态。含义保持一致，并辅以文字或形状；警示色不用于无风险的装饰。
- **辅助色 / 中性色**：组织表面与内容层次。暖冷、明暗与色相的适度变化可以建立层次，不能把低饱和或灰阶本身当成品质。
- **过度去色**：取消有效主色后，主操作识别、表面层次或界面辨识度变弱。修复应恢复颜色的具体作用，不把增加颜色数量当目标。

克制意味着色彩分配有目的、有层次，不意味着单色。配色单调只有在造成具体体验或表达问题时才构成差距；单色与多色方案都可以优秀。

## 常见 AI 感套路（供主控识别与命名）

其中可在代码里机检的已列入 [hard-checks.md](hard-checks.md) A 组，归纳时优先引用 A 组编号。

下列外观是核查线索，不能仅凭某种色相或配色组合断定有 AI 感；须指出无目的装饰、层级干扰或语义误导等具体证据。

- 深色底 + 青色 / 霓虹发光强调；紫蓝渐变；渐变文字（A2）。
- 卡片套卡片（A5）；等大卡片网格铺满（A6）；每个标题上方放圆角图标块。
- 大数字 + 小标签 + 渐变强调的「英雄指标」模板（A4）。
- 装饰性玻璃拟态（A3）、发光描边、通用圆角 + 投影。
- 所有内容居中；间距全程一致没有节奏。
- 用等宽字体冒充「技术感」；emoji 充当界面图标（业务正文自带符号不自动算界面装饰）。
- 单侧粗彩色边框作强调（A1）；装饰性迷你图表。
- 能内联完成的操作用弹窗（A7）。

## 常见设计通病（供主控在归纳阶段识别，非 AI 专属）

- **语义色纪律松散**：告警色（尤其红色）在过多元素上重复使用（数字、徽标、边框、正文强调同时上红），警示力被稀释，真正最该关注的项反而不突出。红色应克制，只留给最高优先级/真风险。
- **焦点分裂**：同屏多个同等量级的巨大数字/元素争抢视线，用户第一眼不知看哪。一屏应只有一个主焦点。
- **同级重复噪音**：长列表里大量行的视觉表现完全相同（同色徽标、同字号），扫读困难；应折叠/分段/分层，把少数需关注项拎出。
- **卡片权重扁平**：所有区块用同一种底色/边框/圆角平铺，缺乏主次，整屏读起来是一张扁平的面。
  - ⚠️ **修复方向容易走反，务必对齐**：正解是**建立层次差异**——给主体区块加阴影/背景色块/更强的圆角与内边距，让次要区块更轻，制造对比。**不是**把区块的边框/分隔一并去掉、改成裸露的通栏加分割线——那样会退化为"没有卡片感、像未排版的原始数据导出"，比扁平更差（见 [execution-constraints.md](execution-constraints.md) X9 与附录）。判断标准：改完之后区块之间的视觉差异应该**变大**，不是变小。
- **信息冗余**：界面组织造成的无任务作用的重复展示，增加噪音而非价值。必要的摘要、详情、编辑与导出可各有用途；源数据的重复记录属于数据核对提示，不按此标签计分或自动安排去重。
