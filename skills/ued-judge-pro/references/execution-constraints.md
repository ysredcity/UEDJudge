# 执行约束（主控 · Step 7）

执行优化时**只需读本表 + 本轮目标设计稿**。本表合并了此前散落在协议、词汇表与执行参考中的"禁止项"。视觉/动效/Web 的具体方法仍在 [visual-optimization.md](visual-optimization.md)、[motion-optimization.md](motion-optimization.md)、[web-interface-quality.md](web-interface-quality.md)，按受影响区域查阅。

约束的目的是**防止改错，不是限制改动力度**。在已批准阶段与目标稿范围内，结构性问题应当做结构性修改，不要因为顾虑而只改表层。

## 约束表

| # | 约束 | 要点 |
|---|---|---|
| X1 | 只做已批准的阶段 | 不新增阶段、不扩大范围；用户只批准部分阶段时只做那部分 |
| X2 | 先有目标稿再动手 | 每条差距写出「目标状态」与「改完应更 X」，对照 [glossary.md](glossary.md) 修复方向确认没理解反（Step 5.5） |
| X3 | 力度与差距匹配 | 结构层差距（构图、层级、分组）做结构性修改；表层差距做局部修改。一个阶段内不叠加多个互相影响的大改 |
| X4 | 保护清单不削弱 | 评论员「做得好的地方」不得变弱；必须改动时在报告写明原因 |
| X5 | 功能保真 | 见下方细则。不删功能、字段、说明、风险提示、操作反馈；不把真实功能换成静态展示 |
| X6 | 文案保真 | 见下方细则。默认原文；只做不改原意的纠错、精炼、澄清 |
| X7 | 数据不动 | 保留原始值与业务正文；数据核对提示不进 UI 阶段；用户另行授权才处理数据 |
| X8 | 删减与语义变化单独授权 | 「同意执行阶段」不等于授权删功能或改语义；先说明原内容、拟改内容和影响 |
| X9 | 建层次 ≠ 去结构 | 分组/权重扁平靠拉开差异解决（底色、阴影、内边距、字号），不是去掉所有容器与分隔。改完区块间差异应变大 |
| X10 | 单一主焦点 | 强调某元素时检查是否制造新的焦点竞争；次要指标不放大成英雄数字 |
| X11 | 色彩先定角色 | 区分品牌/主操作色、语义色、装饰色；降噪先调面积、饱和度、位置、重复次数；不默认去色；增色须对应具体收益 |
| X12 | 视觉改动有契约 | 受影响区域先写焦点、字体角色、色彩角色、表面层级、密度（visual-optimization）；边框默认低权重，装饰 / 控件识别 / 状态分工，不一律调亮，必要识别线索按 hard-checks H2 核验；动效只为状态反馈与因果，不为动效加动效 |
| X13 | 记录改动清单 | 每轮记下改了哪些元素（选择器 / 区块 / 文案），供成对比较归因 |
| X14 | 每阶段后自检与回归 | 自检循环（Step 7）+ 保真核验 + 受影响 H/G/W/M 回归；工具栏/筛选/表单改动必测 G1 |
| X15 | 回退要确认 | 判为真退步时优先回退换根本解法，不在被否定的做法上微调；回退属于修改文件，须用户确认 |

## X5 · 功能保真细则

- 优先改布局、层级、样式与呈现方式。不以降噪、缩短页面或提高评分为由删除功能、数据字段、说明、风险提示或操作反馈；不把真实功能替换成静态展示、示例数据或无实际行为的按钮。
- 移动入口、合并重复呈现、折叠低频内容时，原有能力和信息须仍可发现、可访问、可操作；保持关键状态、输入值与结果反馈，不让高频或关键任务因隐藏而受阻。
- 保真核验（每轮修改后）：对照 Step 5 的保真清单，回归受影响的入口、关键路径、状态和操作结果，检查桌面与相关移动视口的可达性。无法验证的功能如实列出，不宣称全量保留已验证。发现非授权的功能遗漏，先修复；无法安全修复则报告并等待用户选择。分数提高不能抵消功能损失。

## X6 · 文案保真细则

- 修改前后保持操作对象、范围、条件、统计口径、单位、风险、限制、语气强度与承诺一致。不能把「示例」改为「已同步」、「申请」改为「完成」，或为缩短文案删去适用条件。
- 业务专名、数据、乱码或歧义无法可靠确认时，保留原内容并提示核对，不擅自补写或猜改。
- 每轮逐条记录「原文 → 新文案 → 原意为何保持」；无文案改动时注明未改。
