# 通用 Web 界面质量（主控）

Step 4 检查关键路径；Step 5/7 按受影响区域使用。基于 Vercel Web Interface Guidelines 筛选并适配，不要求换框架、添加后端、改产品导航或照搬全部规则。既有 H/G 检查优先，以下补充检查不重复计数、不参与盲评分数；不适用项注明原因。

## W 组 · 工程检查

| # | 适用场景与要求 | 如何验证 |
|---|---|---|
| W1 | 交互语义与焦点：导航使用真实链接，操作使用按钮；浮层按其类型管理进入/返回焦点，固定区域不遮住焦点；手势操作有按钮/键盘替代 | 键盘走关键路径、关闭浮层、打开链接；焦点与键盘失败归 H4/H5，避免重复计数 |
| W2 | 输入完整性：允许粘贴、输入法组合、密码管理器及浏览器缩放；保留编辑内容。校验在字段附近说明，并让用户找到首个错误 | 粘贴、中文输入、校验失败、缩放及重渲染后检查值/焦点；仅在原有流程确有提交时保留其 Enter 约定，不给 textarea 擅自新增提交行为 |
| W3 | 异步与恢复：结果提示可被辅助技术感知；处理重复提交、失败恢复、草稿丢失及危险操作确认/撤销；loading 不改变操作承诺 | 成功/失败/连续点击/离开实测。请求去重按既有后端能力，不伪造幂等保证；缺失关键状态归 H9 |
| W4 | 内容与布局韧性：长标题、长标识、缺失值、稀疏/密集内容不互相遮挡；图片与占位预留空间；锚点目标不被固定区盖住 | 多视口、长短内容、加载前后与缩放实测；允许表格局部滚动，不把它误报为页面溢出。响应式问题归 H10，对齐归 G1 |
| W5 | 导航上下文：已有筛选/分页/标签页若需分享、刷新或返回恢复，则核查 URL/历史及滚动恢复 | 仅同步非敏感、可分享状态；密钥和私密草稿不进 URL。未有该产品需求时不把所有 UI 状态深链接化 |
| W6 | 性能与资源：输入响应不被昂贵渲染拖慢，图片/长列表资源按需要加载，DOM 测量读写不交错造成反复布局 | 对相关设备/浏览器测量；只有确有瓶颈才增加虚拟化或新方案，保留查找、焦点及可访问性。没有测量能力标无法判定，不承诺统一接口时限 |

每项报告 `通过 / 不通过 / 无法判定`，附实际操作、元素或测量证据。聚合项不通过须指明缺失子项；注明与 H/G 重叠的归属。W 组发现的真实阻塞按业务影响进入既有阶段，不因来源名自动升级为“合规阻断”。

## 响应式故障排查路径

发现窄屏、缩放或内容变化导致的问题时，按“复现条件 → 异常元素与父布局 → 局部修复 → 原场景回归”定位。先区分页面级溢出、预期的局部滚动与纯装饰出界；不要通过根节点裁切、隐藏业务内容或缩小所有文字，让溢出数值看似通过。

| 症状 | 优先排查 | 按原因选择的修复方向 |
|---|---|---|
| 页面被一列或长标识撑宽 | 超出视口的元素及祖先的固定宽度、min-width、不可断行内容；Grid/Flex 子项的自动最小尺寸 | 需要收缩的子项可用 `min-width: 0`，需要收缩的 Grid 轨道可用 `minmax(0, 1fr)`；结合内容换行或局部滚动处理，不对整页机械套用 |
| 表格在手机上挤碎或撑开页面 | 表格最小可读宽度、外层是否可收缩、滚动是否发生在预期容器 | 对确需横向比较的表格保留合理列宽，使用局部滚动并保证可操作、能发现后续列；不通过删除列或数据行达成“适配” |
| 筛选区、标题或操作文案互相挤压 | 固定列宽、`nowrap`、无伸缩空间，以及标签/帮助文案是否被混入控件对齐计算 | 按语义分组换行或切换布局，同排控件本体按 G1 对齐；长标题可换行，标识可在显示层断行且复制值不变。不以截断关键条件或强制所有按钮单行为默认解法 |
| 固定栏遮住末行、锚点或键盘焦点 | 实际栏高、滚动容器、堆叠关系、软键盘打开后的可视区域与设备安全区 | 针对占用空间预留滚动余量或定位偏移，必要时改为普通流；在目标设备验证，不能只提高 z-index。保留浏览器缩放，不为键盘问题默认锁死页面滚动 |
| 面板内部不滚动、页面出现意外双滚动 | 高度约束链、Grid/Flex 子项的自动最小高度、滚动归属 | 在应承载滚动的容器限定空间，必要时对子项使用 `min-height: 0`；普通文档保持自然流，不把所有页面改成固定视口应用壳 |
| 数据加载、错误提示或放大文字后布局破坏 | 固定高度、绝对定位、图片占位、长文本与空状态的空间需求 | 让内容区域随文本增长，必要资源预留尺寸；局部裁切仅用于有意越界的装饰，确保正文、焦点与操作入口未被裁掉 |

修复后复跑 H10 既定视口及触发故障的宽度/状态，并检查断点两侧、长中文/长标识和浏览器缩放。页面确有更窄屏使用需求或已发现相关风险时再补 320px，不增加全项目统一测试档位。涉及软键盘或安全区的结论须有对应平台证据，仅改变桌面视口不能宣称移动端行为已验证。

证据保留“触发条件 → 根因 → 改动 → 页面/局部滚动及内容可达性”。溢出修复不代替视觉检查；问题归现有 H10、G1、W1/W2/W4 等适用项，同一问题不重复计数，不另设排查评分。

## 按需采用的打磨建议

- 图标与文字平衡视觉重量，数据比较用等宽数字；单位/快捷键避免无意义断行，格式符合用户语言与业务时区，不猜统计口径。
- 内联说明优于把必要信息塞进 tooltip；tooltip 不成为唯一可达的说明方式。
- 短操作避免加载提示闪烁，可延迟显示指示器；响应已经完成就立即允许继续，不为了最短动画播放时间拖延用户。
- 移动输入字体可采用至少 16px 避免部分浏览器自动放大，但不禁用用户缩放；原文、密码和标识不因“清理空白”或自动翻译而改变。
- 对刘海安全区、始终显示滚动条、原生 select 配色、触屏 hover 缺失等问题，在相关目标平台验证；未经实测不宣称跨平台通过。

这些建议不是统一外观模板，不强制更换字体、为所有按钮添加缩放、把所有加载改为骨架屏，或添加无产品需求的快捷键。动效执行与验证见 [motion-optimization.md](motion-optimization.md)。
