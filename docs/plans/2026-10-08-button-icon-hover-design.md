# 按钮对比、操作图标与输入悬停检查修订

日期：2026-10-08。用户提出三项明确修正；本轮只改 skill 规则，保留原始 TC1、历史优化稿、版本包与已有未提交台账，不自动提交、推送或安装。

## 问题与方案

- 1.4.1 的「默认组件边框无独立下限」范围过宽，可能被解释为按钮也不用检查。改为按控件用途区分：输入默认边框/底色不统一提亮，按钮必要识别对比必须核验；可操作文字/图标已足够的按钮不要求填充和边框同时高对比。复选/开关等状态控件、输入内操作按钮不属于输入放宽。
- H7 只检查文字，按钮图标偏小未单独核验。原始 TC1 的按钮字体 12px，⟳/📋 混在文本中继承字号，眼睛入口也是 12px；CSS 还包含 10×6 的下拉箭头。小字号是核查线索，不仅凭数值判图标失败。扩充现有 H7，不新增评分维度或单独检查编号。
- H9 只泛称「与用途相关的状态」，可被执行者忽略输入 hover。原始 TC1 自定义输入仅有 focus，主按钮有 hover，幽灵按钮没有对应自定义样式。明确精细指针场景逐类实测输入/选择控件与按钮的移入、移出和焦点叠加；原生反馈有效可以沿用，无 hover 设备、禁用与只读按用途处理。

采用现有 H2/H7/H9＋视觉参考/X12/X14 与索引修订，不引入组件库、固定 CSS 范例、全端大控件或全局亮边框。按问题加载，Pro 共用文件由脚本生成。整体版本暂留 1.4.1 / Pro 1.0.1，修改记入 Unreleased，不覆盖已有 ZIP。

## 必须保留的边界

1. 输入类默认轮廓不设统一数值目标，不等于已证明 WCAG AA 合规；若实际唯一必要线索不足仍如实记录，不用 hover/focus 替代默认识别。
2. 按钮检查实际填充/轮廓/图标或可操作文字，不机械要求全部边框 ≥3:1；按钮文字仍按文字对比检查，必要非文字线索按 H2。
3. 16–20px 文字按钮图标、20–24px 纯图标是无设计体系时的试配起点，不是 WCAG 最小尺寸或强制组件规范；原有设计体系优先，以实际辨识与图文重量判断。
4. 图标可见大小、按钮真实命中区与控件高度分别核验；不得以图标偏小为由统一放大页面。
5. hover 有可感知、可恢复的视觉变化即可，不要求默认/hover 两状态互达 3:1，不引入单侧亮线、不覆盖焦点/错误，不为演示强制运动。
6. 图标与 hover 工程检查不传给评论员，不改变冻结分数或调用预算；静态检查与原始页测量不证明新 skill 行为改善。
