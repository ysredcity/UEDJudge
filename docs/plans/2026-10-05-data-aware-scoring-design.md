用户要求撤回上一轮本地规则补充、恢复当前云端版本，并解决原始数据保真与评分扣分的冲突。先恢复已核验的 `origin/main` 提交 `e69dee6d9b56cbc65bee97f7f2a68db7a684965b`，再单独实施以下修订，不修改页面或历史分数。

## 边界

- 业务数据本身的问题只提出核对建议，不计分；不能猜改、删记录来提高 UI 分数。
- 界面文案及独立可见的呈现问题仍评价；混合问题拆开，归因不明时只提示。
- 必要摘要、详情与导出重复允许，无目的的界面重复仍可扣分。
- 数据核对提示不占五条界面差距名额，不自动触发阶段或新功能。
- 冻结 prompt 升至 v2.2，全程同口径；六维锚点、评分换算、隔离、闸门、成本上限不放宽。旧口径分数不与新口径直接比较。

## 边界场景核查（规则走查，非独立盲评）

| 场景 | 应有判断 |
|---|---|
| 数据标题乱码、重复记录、日期异常、总数矛盾 | 数据核对提示；不计分，不猜改 |
| 按钮“已同步”却仅表达申请，操作范围提示不明确 | 界面文案问题；按独立可见证据评价，不能臆测后台行为 |
| 原始报告很长，同时编辑栏过窄、文字被遮挡 | 长度本身不计分；列宽或遮挡的独立呈现问题可评价 |
| 同一需求出现在任务清单与可复制日报正文 | 各有用途时不算无目的冗余；不自动删正文 |
| 日期单元格显示优先级，无法判定来源或绑定问题 | 归因不明提示，不计分；源码核对由主控另行处理 |
| 数据含符号，同时全页字号小、低对比 | 符号不自动当装饰；字号、对比度缺陷仍检查 |

已完成规则走查及静态一致性检查；尚未验证评论员在真实截图中是否稳定遵守分类，不能据此宣称盲评效果或分数提升。
