# 控件识别、指标整体性与密度修订（用户已确认）

日期：2026-10-08。

## 依据与取舍

用户指出最新 TC1 产物的深色输入边框过亮、指标组缺少整体性、控件偏大，并确认按分析建议补充规则。本轮修正主控的检查与执行决策，不重做页面、不改冻结评分正文。

实跑中，控件完整描边承担了主要识别作用，输入框及按钮从 34px 全端放大到 44px；六指标被拆为一张强调卡与五组无共同表面的数字。这些是执行选择，不是可访问性标准要求的唯一实现。采取条件化指导，不引入固定配色、尺寸区间、卡片结构或组件范例。

## 修订范围

- H2：先识别必要线索，再选择低噪的实现；线索满足对比不等于整圈边框统一高亮。保留必要线索 3:1 与默认可发现性，不能以静态标签或仅有聚焦态豁免输入识别。
- H8：区分 WCAG 2.2 AA 的 24×24 CSS px 及适用例外，与 AAA 44×44 的增强目标；触屏按实际用途推荐增强，不全端强制。区分可见尺寸和真实点击区域，扩展须实测有效且不重叠、不误触。
- X9/X10/X12 与视觉参考：组间主次清楚、组内关系连贯；重点可局部突出，不靠拆散同组信息或整体放大实现层级。
- A5/A6 与词汇表：有语义的分组层级和用于比较的同质指标布局不自动构成反模式，指出无任务作用的套框、装饰或层级干扰才安排修复。
- SKILL 仅补充相关参考的加载提示；Pro 共用文件通过现有脚本生成，不双份维护。

## 边界与验证

普通版 1.3.0、Pro 1.0.0 不变，变更列入 Unreleased；critic v3.1、verifier v1、流程、评分项、报告模板、闸门和调用上限不变。不全局安装、不打包、不提交或推送。

检查两套 skill 结构、本地链接、Pro 12 文件同步、现有 Pro 测试、diff 与冻结文件/两份 TC1 HTML 哈希。人工用紧凑桌面控件、触屏增强、空输入默认识别、同组指标比较及无目的重复套框等场景检查新规则边界。该检查不等同于新的模型优化实跑或审美收益证明，后续实跑须由用户另行发起。

## 完成检查

两套 quick_validate、12 文件同步检查、6 项 Pro 测试、45 个本地链接及 diff 检查通过。critic / verifier / protocol / report-template 及原始 TC1、20261008 产物共 6 文件 SHA-256 与本轮修改前一致。

以下为主控的人工规则边界复核，不是新评论员调用或浏览器效果测试：

| 场景 | 新规则的判定路径 |
|---|---|
| 桌面 160×32px 的真实操作区域，原密度有效 | H8 尺寸满足最低要求，不因触屏增强目标统一放大到 44px |
| 触屏目标未达 44px，但满足 AA 最低要求且未有显式增强要求 | 不仅凭未达 44px 判失败；按任务、误触风险考虑增强 |
| 空输入默认态无法识别，仅 focus 有亮框 | 焦点合格不能替代默认识别；H2 仍需修复 |
| 必要局部边界具有足够对比，其余描边仅装饰 | 核验必要线索，不要求其他边框同步高亮 |
| 六个对齐、成组且有主次的同形指标用于比较 | 不自动命中 A6；保留一致性，不为去模板化拆散 |
| 有语义的区域包含状态子项 | 不因嵌套自动命中 A5；重复套框无作用且增加噪音才修复 |
| 布局盒够大但实际命中区域未扩展，或扩展后与邻项重叠 | 不能按占位盒通过 H8；需实测真实点击范围与误触 |
