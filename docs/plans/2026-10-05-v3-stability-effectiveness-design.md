# v3：评分稳定性与优化效果改造（设计记录）

用户反馈两个问题：多次评分稳定性有偏差；实际优化效果未达预期。用户确认「三档一起做」，并接受初评双样本带来的调用增加，以及成对比较对隔离规则的放宽。

## 根因

稳定性：单评委绝对分的整体严格度偏移（±1 同向累加）；相邻档位靠程度副词区分；先打分后补依据；打分段含"大胆、有主见""世界顶尖"放大波动；长整页截图被模型压缩导致细节不可读；v2→v2.2 连续改口径未验证；评委模型未固定；9 分线（≥22/24 且取较低）几乎不可达。

效果：诊断与执行之间没有目标设计；规则一路打补丁成为防御性清单，执行趋于浅改；以噪声大的总分衡量成败；一次性执行没有中间反馈；L2/L4 计数与保真冲突；数据类差距不可改善但未告知用户。

## 决策

| 档 | 改动 | 文件 |
|---|---|---|
| 降噪 | 总览 + 1440×900 视口切片截图脚本（像素密度 1：模型本身会把图压到约 1.15MP，2 倍密度收益有限，切片才是关键） | `scripts/capture.mjs`、protocol Step 2 |
| 降噪 | 初评双样本取平均，差距与勾选缺口分高/低置信 | protocol Step 3 |
| 降噪 | 固定评委模型；不能固定时记录 | protocol Step 3、§4 |
| 降噪 | 9 分线降为远景参考，改用四条务实目标 | protocol Step 8 |
| 机制 | 冻结 prompt v3：24 条可观察勾选项，满足条数即维度分；举证责任在「不满足」；先证据后计分；打分段去掉放大波动的措辞；数据边界压缩为 4 条 | `critic-prompt.md` 正文 A |
| 机制 | 复评改为成对比较，随机 A/B、不告知新旧；依据指向本轮改动才判真实变化 | `critic-prompt.md` 正文 B、protocol Step 7 |
| 效果 | Step 5.5 目标设计稿；阶段表每条写可观察目标状态 | protocol、report-template |
| 效果 | 主控截图自检循环（≤2 轮，不计调用） | protocol Step 7 |
| 效果 | 差距核验员：收尾逐条判定初评差距是否解决，不打分 | `verifier-prompt.md`、protocol Step 8 |
| 效果 | 执行约束合并为 X1–X15，实测教训移附录；执行只读约束表 + 目标稿 | `execution-constraints.md` |
| 效果 | L2/L4 改为「超出时须有主次/分组」 | `hard-checks.md` |
| 效果 | 报告新增「可改善上限」 | protocol Step 5、report-template |

成本：子智能体调用 只要报告 2 / 一次性 5 / 逐阶段 ≤7（评论员 2/4/≤6 + 核验员 0/1/1）。

## 取舍

- 收尾只保留 1 次绝对评分（而非双样本），以控制调用；成败主要看核验与成对比较，绝对分仅作参考。
- 逐阶段的成对比较对比「上一保留版本 vs 本阶段」，归因清楚；整体改善由核验员对初评差距的逐条核对体现。
- 核验员知道改前改后，因为它只验收不评优；评论员仍完全盲评。

## 验证

见 `_tests/experiments/2026-10-05-v3-calibration/results.md`（不入库）与 `PROJECT_CONTEXT.md`。TC1 同截图 3 样本总分极差 1.7 → 0.8；成对比较与核验员在 v5→v6 上识别出 v2 绝对分掩盖的排版退步。单案例、小样本，仍需扩充。
